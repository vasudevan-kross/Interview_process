# Free Hosting: Vercel (frontend) + Render (backend), AI evaluation local

Candidates take technical assessments on the hosted site. AI work (evaluation,
question extraction from documents, OCR, resume parsing) runs only on your local
machine with Ollama. Both deployments use the same Supabase project, so results
evaluated locally show up on the hosted dashboard.

```
Candidates ──> Vercel (Next.js) ──proxy /api/v1──> Render (FastAPI, LLM_ENABLED=false) ──┐
                                                                                           ├──> Supabase
You ──> local frontend + backend + Ollama ──> "Evaluate all" ──────────────────────────────┘
```

On the hosted backend, AI endpoints return **503 "AI features are disabled on this
server"** instead of silently saving 0 marks.

---

## 0. Before you start

- Code pushed to a **GitHub** repo (private is fine). Both Vercel and Render deploy from GitHub.
- From `backend/.env`, have ready: `SUPABASE_URL`, `SUPABASE_KEY` (service role), `SUPABASE_ANON_KEY`,
  and optionally `GMAIL_SENDER` / `GMAIL_APP_PASSWORD`.
- From `frontend/.env.local`, have ready: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`.

Never commit these values. Paste them only into the Vercel / Render dashboards.

---

## 1. Deploy the backend on Render

### 1.1 Create the account
1. Go to https://render.com → **Get Started**.
2. Choose **Sign up with GitHub** and authorize Render.
3. No credit card is needed for the free plan.

### 1.2 Create the service from the Blueprint
1. In the Render dashboard: **New +** → **Blueprint**.
2. **Connect a repository** → pick this repo. If it is not listed, click
   **Configure account** and grant Render access to the repo.
3. Render reads `render.yaml` from the repo root and shows one service: `interview-api`.
4. Fill in the values it asks for:

   | Key | Value |
   |---|---|
   | `SUPABASE_URL` | from `backend/.env` |
   | `SUPABASE_KEY` | service role key from `backend/.env` |
   | `SUPABASE_ANON_KEY` | from `backend/.env` |
   | `FRONTEND_URL` | `https://placeholder.vercel.app` for now (fixed in step 3) |
   | `ALLOWED_ORIGINS` | same as `FRONTEND_URL` |
   | `GMAIL_SENDER` / `GMAIL_APP_PASSWORD` | optional, leave blank if unused |

5. Click **Apply**. The first build takes ~3–5 minutes.
6. When it shows **Live**, copy the URL, e.g. `https://interview-api.onrender.com`.
7. Check it: open `https://interview-api.onrender.com/api/v1/health` → should return
   `"status": "healthy"` and `"debug_mode": false`.

> Free Render services sleep after 15 min without traffic; the next request takes ~1 minute.
> Step 5 below keeps it awake.

---

## 2. Deploy the frontend on Vercel

### 2.1 Create the account
1. Go to https://vercel.com/signup.
2. Choose **Hobby** (free) → **Continue with GitHub** → authorize Vercel.

### 2.2 Import the project
1. Dashboard → **Add New…** → **Project** → **Import** this repo
   (use **Adjust GitHub App Permissions** if the repo is not listed).
2. **Root Directory** → click **Edit** → select `frontend`. Framework is detected as **Next.js**.
3. Leave Build / Install commands at their defaults (`frontend/.npmrc` already sets
   `legacy-peer-deps`).
4. Open **Environment Variables** and add:

   | Key | Value |
   |---|---|
   | `BACKEND_URL` | your Render URL, e.g. `https://interview-api.onrender.com` (no trailing slash) |
   | `NEXT_PUBLIC_API_URL` | *leave unset / empty* — all calls go through the `/api/v1` proxy |
   | `NEXT_PUBLIC_SUPABASE_URL` | from `frontend/.env.local` |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | from `frontend/.env.local` |
   | `NEXT_PUBLIC_FRONTEND_URL` | `https://placeholder.vercel.app` for now (fixed in step 3) |

5. Click **Deploy** (~2–4 minutes). Copy the production URL, e.g. `https://interview-xyz.vercel.app`.

`BACKEND_URL` and `NEXT_PUBLIC_*` values are baked in at build time — after changing any of
them you must **Redeploy**.

---

## 3. Point everything at the real URLs

1. **Render** → `interview-api` → **Environment**: set `FRONTEND_URL` and `ALLOWED_ORIGINS`
   to your Vercel URL → **Save Changes** (auto-redeploys).
2. **Vercel** → Project → **Settings → Environment Variables**: set `NEXT_PUBLIC_FRONTEND_URL`
   to your Vercel URL → **Deployments** → latest → **⋯ → Redeploy**.
3. **Supabase** → **Authentication → URL Configuration**:
   - **Site URL**: your Vercel URL
   - **Redirect URLs**: add `https://<your-app>.vercel.app/**` and keep `http://localhost:3000/**`

---

## 4. Configure the local (AI) setup

Interview links are generated by whichever backend creates the interview and saved in the
database, so the local backend must also produce Vercel links.

- `backend/.env`: set `FRONTEND_URL=https://<your-app>.vercel.app`
  (leave `LLM_ENABLED` unset — it defaults to `true` locally).
- `frontend/.env.local`: set `NEXT_PUBLIC_FRONTEND_URL=https://<your-app>.vercel.app`.

Restart the local backend and frontend after editing.

---

## 5. Keep the backend awake (optional, recommended)

1. Create a free account at https://cron-job.org (or https://uptimerobot.com).
2. Add a job that requests `https://interview-api.onrender.com/api/v1/health` every **10 minutes**.

Without this, the first candidate after a quiet period waits ~1 minute for the page to load.

---

## 6. Daily workflow

1. **Create the interview** — locally if you upload a question document (needs the LLM);
   manual questions can be created on either deployment.
2. **Send the link** — it points to Vercel. Your PC can be off.
3. **Candidates take the test** on Vercel → Render → Supabase.
4. **Evaluate**: start Ollama + local backend + local frontend, open the interview, click
   **Evaluate all**. Scores are written to Supabase and appear on the hosted dashboard too.

## What only works locally

| Feature | Hosted behaviour |
|---|---|
| Evaluate / Evaluate all | 503 with "run locally" message |
| Extract questions from document | 503 |
| AI question generation, resume matching, answer-sheet OCR | fails with the "AI features are disabled" error |
| Resume auto-processing after a candidate submits | skipped (logged on Render); not retried later |
| Voice screening (Vapi) | not set up for hosting |

## Free-tier limits to know

- **Vercel Hobby**: non-commercial use only.
- **Render free**: 512 MB RAM, sleeps after 15 min idle, 750 instance-hours/month,
  outbound SMTP ports blocked (Gmail emails will not send from Render — send invites locally).
- **Supabase free**: project pauses after ~1 week with no activity; un-pause from the dashboard.
